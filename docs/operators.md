# Operators

| Id | Bytecode change | Kotlin before / after | Known equivalent mutants |
|---|---|---|---|
| `negate-conditionals` | `IFEQ`/`IFNE`, `IFLT`/`IFGE`, `IFGT`/`IFLE`, `IF_ICMPEQ`/`IF_ICMPNE`, `IF_ICMPLT`/`IF_ICMPGE`, `IF_ICMPGT`/`IF_ICMPLE`, `IF_ACMPEQ`/`IF_ACMPNE` swap to their negation | `if (a < b)` compiles to `IF_ICMPGE`, mutated to `IF_ICMPLT` (condition inverted) | Rare; a condition guarding two identical branches. `IFNULL`/`IFNONNULL` are never emitted: null checks belong to `null-safety`. |
| `arithmetic` | I/L/F/D `ADD`<->`SUB`, `MUL`<->`DIV`, `REM`->`MUL`. Unary `NEG`, `IINC` and string concatenation are not sites. | `a + b` / `a - b`; `a * b` / `a / b`; `a % b` / `a * b` | `x + 0`, `x - 0`, `x * 1`, `x / 1`; `x * 0` vs `x / 0` is not equivalent for int (throws). |
| `conditionals-boundary` | `IFGE`<->`IFGT`, `IFLE`<->`IFLT`, `IF_ICMPGE`<->`IF_ICMPGT`, `IF_ICMPLE`<->`IF_ICMPLT`. Long and double compare via `LCMP`/`DCMPx` then `IFxx`, so they are covered by the `IF*` rows. `IF_ACMP*` is not mutated. | `a < b` / `a <= b`; `x >= 0` / `x > 0` | Loop or range bounds where the equal case is unreachable (`i < n` with `i != n` guaranteed); `> Int.MAX_VALUE`-style guards |
| `null-returns` | `ARETURN` becomes `POP`, `ACONST_NULL`, `ARETURN` for methods returning an object type, except arrays and `java.util` `List`, `Set`, `Map`, `Collection` (left to `empty-returns`). An `ARETURN` directly after `ACONST_NULL` is not a site. | `return name` / `return null` (also for Kotlin non-null return types, where callers fail with an NPE) | Methods whose result callers never use; a return already null on every path that reaches it through a merge label |
| `return-vals` | `IRETURN`/`LRETURN`/`FRETURN`/`DRETURN` become `POP`/`POP2`, zero constant, same return. Boolean (`Z`) returns, reference returns, `void` and returns directly after a zero constant are not sites. | `return x` / `return 0` (`0L`, `0f`, `0.0`) | Primitive fields/values that are already zero |
| `empty-returns` | `ARETURN` becomes `POP`, an empty value, `ARETURN` for methods returning an array (`new T[0]`, component type kept) or `java.util` `List`, `Set`, `Map`, `Collection` (`Collections.emptyList()`/`emptySet()`/`emptyMap()`; `Collection` gets an empty list). The empty value is the shared `java.util.Collections` singleton, or a fresh zero-length array. A return directly after an empty-collection factory call or a zero-length array creation is not a site. | `return items` / `return emptyList()` | Methods whose result callers never use; a return already empty on every path that reaches it through a merge label |
| `constructor-calls` | The whole `NEW`, `DUP`, args, `INVOKESPECIAL <init>` sequence is replaced by the args popped (`POP`/`POP2` per descriptor) and `ACONST_NULL`. Nested constructions are separate sites (inner first). `super()`/`this()` calls, `StringBuilder` constructions (string templates), constructions directly followed by `ATHROW` (`throw X()`) or `ARETURN` (a returned construction is `null-returns` territory) and any other shape are not sites. | `Box(a)` / `null` (callers fail with an NPE, or null reaches a null-checked parameter) | Objects whose constructor has no effect and whose value is never used |
| `increments` | `IINC` with a non-zero increment has its sign flipped (`i++` to `i--`, `i += 5` to `i -= 5`). Wide `IINC` (increments beyond a byte) is flipped too, except -32768, which has no positive counterpart. Kotlin emits `IINC` only for small int constants (`i += 1000` is `IADD`, a site of `arithmetic`); long, float and double increments are also `ADD`. | `i++` / `i--`; loop counters of `for`, `while` and `do` | A counter whose value is never read; loops that then never end are reported as TIMEOUT, not equivalent |
| `true-returns` | In methods whose descriptor ends in `Z`, `IRETURN` becomes `POP`, `ICONST_1`, `IRETURN`, whatever computed the value (constant, local, comparison, call). An `IRETURN` directly after `ICONST_1` is not a site. | `return a > 0` / `return true` | Methods that already return true on every path through a merge label; unused results. Shares each `IRETURN` with `false-returns` but the mutants differ. |
| `false-returns` | Same as `true-returns` with `ICONST_0`. | `return a > 0` / `return false` | As `true-returns` with false |
| `void-method-calls` | An `INVOKEVIRTUAL`/`INVOKEINTERFACE`/`INVOKESTATIC` returning `void` is replaced by pops for its arguments (`POP2` for long/double) and receiver, or a `NOP` when nothing is on the stack. Void `JobKt` statics (`ensureActive`) belong to `coroutine`. `INVOKESPECIAL` is a site only for a private method of the class itself (found through the `this` local variable, so classes without debug info get none); constructors and super calls, `invokedynamic` and compiler plumbing (`kotlin/jvm/internal/*` such as `Intrinsics`, `kotlin/coroutines/intrinsics/*`, `kotlin/coroutines/jvm/internal/*`, `ResultKt`) are not sites. | `log(x)` / (call removed) | Calls without observable effect (logging, caches, idempotent setters). String templates compile to `StringBuilder.append`/`toString` calls and `Intrinsics.areEqual` backs `==`: all become noisy, mostly equivalent mutants, so `kotlin/jvm/internal/*` (including `Intrinsics`) is skipped but `StringBuilder` calls are not. |
| `non-void-method-calls` | An invoke returning a value is replaced by the same pops and the return type's default: `ICONST_0` (int, boolean, byte, char, short), `LCONST_0`, `FCONST_0`, `DCONST_0`, `ACONST_NULL` (objects and arrays). `kotlin/Unit` returns and suspend calls (last parameter `Continuation`) are not sites; exclusions as for `void-method-calls`; data class `copy` calls belong to `data-class-copy`; coroutine builder and suspend calls belong to `coroutine`. | `val n = repo.count()` / `val n = 0`; `name()` / `null` (callers fail with an NPE) | Results already zero/null; results that are discarded or only used by logging. Overlaps by effect, not by bytes, with `null-returns`/`return-vals` for `return f()`. |
| `sealed-when` | Makes one `when` branch unreachable. A type test becomes false (`INSTANCEOF` is replaced by `POP`, `ICONST_0`; the object-branch `Intrinsics.areEqual(subject, X.INSTANCE)` by `POP2`, `ICONST_0`) when the same local is tested at least twice in the method, so a branch is skipped for the next one or the else path. An enum `when` (`TABLESWITCH`/`LOOKUPSWITCH` on `ordinal()`, with or without the `$WhenMappings` array) gets one site per body: its cases are redirected to the switch default (cases already going to the default, such as the unmapped ordinal 0 of a nullable `when`, are not sites). A lone type test, tests on different locals, a one-entry enum `when` (a plain comparison, left to `negate-conditionals`) and Int or String switches are not sites. | `is Circle -> a` / branch never taken: falls to the next branch, the else, or `NoWhenBranchMatchedException`; `Color.RED -> 1` / `RED` goes to the default | A branch no test reaches; a branch whose body equals the else body; the last branch of an exhaustive when whose type the subject can never have. The rule fires on any two type tests of one local, sealed hierarchy or not (the operator sees no class hierarchy), and a reused local slot can credit tests of two unrelated variables to one chain. Site descriptions name the switch key (a `$WhenMappings` index), not an enum entry or ordinal. |
| `null-safety` | `IFNULL`<->`IFNONNULL` swap. A call to `kotlin/jvm/internal/Intrinsics.checkNotNull`, `checkNotNullParameter`, `checkNotNullExpressionValue` or `throwUninitializedPropertyAccessException` is replaced by pops for its arguments (the compiler follows the lateinit throw with `ACONST_NULL`, so the getter then returns null). `throwNpe`/`throwJavaNpe` are not sites. Not gated on `@kotlin.Metadata` (a Java null check is flipped too); methods the framework skips (constructors) get no site. | `s?.length`, `s ?: d`, `s == null` flip their branch; `s!!`, a parameter check, a platform-type result check or a `lateinit` read stops failing fast | Parameter checks (`checkNotNullParameter`) are typically equivalent for Kotlin callers, which cannot pass null, so removing them only matters for Java or reflective callers; a platform check whose value is never dereferenced; a flipped branch where both arms agree. Constructor parameter checks produce no sites (constructors are skipped centrally), which legacy 0.3.3 did not do. |
| `data-class-copy` | A call recognised as a data class copy is replaced by pops for its arguments (`POP2` for long/double) and receiver, then `ACONST_NULL`. Two shapes: `INVOKEVIRTUAL owner.copy(...)` with at least one argument returning `owner`, and `INVOKESTATIC owner.copy$default(owner, ..., int, Object)` returning `owner` (the default-argument bridge). Call sites live in other classes than the data class and a method has no class context, so the rule is structural: a plain class with a same-shaped `copy` method is a site too. Independent of the order of methods and classes. Lookalikes that are not data classes (`Bitmap.copy`, a user `copy` returning its own type) are claimed by this operator, not by `non-void-method-calls`. A value class property mangles the name to `copy-<hash>`: such calls are not matched and stay `non-void-method-calls` sites. | `p.copy(x = 1)` / `null` (callers fail with an NPE) | Copies whose result is unused. For `return x.copy(...)` the effect overlaps with `null-returns`/`return-vals` (different instructions, same visible outcome). Calls of this shape are not sites of `non-void-method-calls` (it would emit the same mutant). |
| `coroutine` | A static call on `kotlinx/coroutines/BuildersKt` (`launch`, `async`, `runBlocking`, `withContext`) or `JobKt` (`Job()`, `ensureActive`), or a call of a suspend function (`INVOKESTATIC`/`INVOKEVIRTUAL`/`INVOKEINTERFACE`, or `INVOKESPECIAL` of a private method of the class itself, whose descriptor ends `Lkotlin/coroutines/Continuation;)Ljava/lang/Object;`, or `Continuation;ILjava/lang/Object;)Ljava/lang/Object;` for the `foo$default` bridge of a suspend call with default arguments), is replaced by pops for its arguments and receiver and the return type's default (null for objects, nothing for `void`). The suspension marker `IntrinsicsKt.getCOROUTINE_SUSPENDED()`, the `kotlin/coroutines/intrinsics/*` and `jvm/internal/*` helpers, `ResultKt.throwOnFailure` and `Boxing` are never sites, so label switches and suspension checks stay as the compiler wrote them: the replaced call simply completes at once with null. The call that resumes a suspend function from its continuation class (an `invokeSuspend(Object)` storing a `result` field; a method sees no class, so the superclass is not checked) is not a site. `GlobalScope` has no statics: `GlobalScope.launch` is a `BuildersKt` call. Independent of the order of methods. | `val j = launch { work() }` / `val j = null` (`j.join()` fails with an NPE); `launch { work() }` as a statement / the launch is dropped; `val n = fetch()` / `null` (callers unboxing it fail with an NPE) | `delay(...)` (a skipped delay changes timing only); calls whose result is unused and whose effect is covered by `launch` fire-and-forget tests that do not wait. Needs kotlinx.coroutines on the mutated code's classpath to produce builder sites; suspend calls need only the stdlib. Calls of this shape are not sites of `void-method-calls` or `non-void-method-calls` (they would emit the same mutant). |

## Noise filters

Site filters (`mutkt-asm/.../asm/filters`) recognise compiler-generated instructions only; user code is never filtered. They run inside site enumeration (`sitesOf`), so `discover` and `mutate` see the same list and an ordinal is an index into the filtered sites. Operators do not know about filters. Counts are sites of all operators on the `ContractCorpus` (466 before, 404 after, 13% fewer) and on the parity fixtures (359 before, 336 after).

| Rule | Recognised by | Sites removed (corpus / parity) |
|---|---|---|
| `InlinedBodyFilter` | Instructions whose innermost kotlinc marker is a `$i$f$name` local variable (an inline function body copied into a caller). The marker named after the method itself (the inline function's own body) and `$i$a$` lambda bodies, which the user wrote, stay. | 33 / 22 |
| `InlinedClassFilter` | In a regenerated `Caller$f$$inlined$g$1` class, everything outside `$i$a$` lambda bodies. Without debug info nothing is recognised. | 4 / 0 |
| `StringWhenFilter` | `s.hashCode()` before a switch whose every case leads to `s.equals("constant")`, and those `equals` calls (a `when` on a String with at least three branches). A user `when (s.hashCode())` is not matched. The branch jumps stay. The match is structural, so a hand-written `switch (s.hashCode())` whose every case runs `s.equals("constant")` right away would be dropped too (not seen in compiler output of ordinary code). | 8 / 0 |
| `WhenMappingsFilter` | Only the `ordinal()` call after `GETSTATIC X$WhenMappings.$EnumSwitchMapping$n; SWAP` (an enum `when`). The switch, the table lookup and the branches stay, so `sealed-when` sites on enum switches are not hidden (the sealed-when tests pass). The user's own `table[e.ordinal]` has no `SWAP`. | 4 / 1 |

Not filters, because nothing needs one: `$default` bridges and the `$WhenMappings` class (synthetic or only `<clinit>`, skipped by the skip rules: 0 sites before and after), and `Intrinsics.areEqual` and the lateinit `throwUninitializedPropertyAccessException` (`kotlin/jvm/internal/*` calls are not sites of the call operators; the null checks around them belong to `null-safety`).
A user-defined inline function is not mutated at all: `isMutable` skips a method whose own `$i$f$<its name>` marker runs to the end of the body (`isInlineFunctionOriginal`, shared with `InlinedBodyFilter`; the marker of a copy ends before the caller's return, so a regular method named like the inline function it calls stays mutable and its copy is filtered; mangled names of internal and value-class functions appear in the marker unchanged), so neither the original body nor its copies in callers are sites, and the original would otherwise leave survivors that only a Java or reflection call could kill. Callers' own code stays mutated. Blind spot: Java callers and function references of inline functions are not mutation-tested; a `::inlineFn` reference compiles to a regenerated class whose `invoke` holds a copy of the body (no call of the original). The marker is a local variable, so a class compiled without debug info still has its inline functions mutated.

## Suppression

`@SuppressMutations(operators = [...], reason = "...")` on a class or function skips mutants: no `operators` means all, otherwise only the listed ids (unknown ids fail the run and list the valid ones).
Class and function suppression are unioned. Nested, inner, companion and anonymous classes inherit from the enclosing class, and anonymous classes also from the enclosing function.
A function's lambda bodies (`f$lambda$N`) are suppressed with it; they match by name, so every overload named `f` covers them. A function's own annotation matches name and descriptor.
Limits: inline function bodies are never mutated (see Noise filters), so suppressing one has no effect. Property accessors are suppressed only through their class.
